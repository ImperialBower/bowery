# The element

Builds on [frame and draw](frame-and-draw.md).

- **Two Rust layers, both behind `wasm`.** `src/element.rs` holds all the
  logic in plain Rust and is tested natively (`cargo test --features wasm`).
  `src/wasm.rs` only wraps it. Doc tests of `wasm.rs` show success paths only:
  building a `JsValue` (every error path does) panics on a native target.
- **Names.** wasm-pack's `--out-name bowery_wasm` gives `bowery_wasm.js` and
  `bowery_wasm_bg.wasm`; the element is `js/bowery.js`.
- **Size gate.** `make size` builds with `wasm-pack` (release, `wasm-opt -Oz`
  from `package.metadata.wasm-pack`) and fails above `WASM_GATE` in the
  `Makefile`: the measurement (1,295,901 bytes, 22 October 2026) plus 10%.
- **JS.** `js/bowery.js` holds one shared module per `base`. Each element
  constructs its own `BoweryTable`. The SVG goes in through `innerHTML`,
  which is safe only because `draw` escapes every config text. Symbol buttons
  need `aria-label`.
- **Demo.** `make site` writes `site/` (git-ignored): `site/bowery/` is what
  a release ships, and the configs and fallback stills sit beside it. The
  replay and interactive configs are generated by indenting
  `fixtures/the_hand.yaml` under `hand:`, so they never drift from it.
  `make serve` serves it on port 8000.
- **Guides.** `demo/guide/` holds one page per demo table, copied to
  `site/guide/` by `make site`; their tables use `base="../bowery/"` and
  the configs one level up. A shown config is marked `data-config` (whole
  file, byte for byte) or `data-config` plus `data-abridged` (the file's
  lines in order, `# …` lines for the gaps); `tests/e2e/guide.spec.ts`
  holds them to the files. Their CDN links are pinned like the README's and
  `scripts/dist.sh` checks both.
